5	## Overview
6	
7	Half-Life combines The Composable Architecture (TCA) with Clean Architecture (constitution Article I). The code is split into three layers, and dependencies always point inward, toward Domain.
8	
9	| Layer | Contains | May depend on |
10	|-------|----------|---------------|
11	| Presentation | TCA features: reducers and views | Domain |
12	| Domain | Entities, single-purpose use cases, repository protocols | Nothing |
13	| Data | Repository implementations and data sources | Domain |
14	
15	Data flows in one direction:
16	
17	```
18	 Command:  View ─▶ Action ─▶ Reducer ─▶ Effect ─▶ UseCase ─▶ Repository ─▶ DataSource
19	 Update:   Repository ─▶ AsyncStream ─▶ Observe…UseCase ─▶ Action ─▶ Reducer ─▶ State ─▶ View
20	```
21	
22	Repositories are the single source of truth. A feature never writes repository-owned data into its `State` directly. It sends a command through a use case, and the new data arrives back through its observation.
23	
24	> Important: One decision is still open. The app target defaults to `MainActor` isolation (`SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`), and TCA reducers crash under that setting. Annotating TCA types `nonisolated` leaves compiler warnings, while a `nonisolated` target default works cleanly. The patterns below assume this has been settled. Settle it before building the first feature, then update this note.

27	
28	| Kind | Lifetime | Holds state? |
29	|------|----------|--------------|

31	| Use case | The owning feature | No, only references to repositories |
32	| Feature `State` | The feature's presentation | Yes, a reduced projection of repository data plus UI state |
