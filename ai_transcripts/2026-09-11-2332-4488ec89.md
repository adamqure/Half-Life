### 23:34:33 · Claude

You can't get it silently. iOS doesn't let an app read the user's name without them doing something. The closest you can get is one tap instead of typing. I'm answering from memory of Apple's APIs and haven't checked current docs or tried anything on a device.

**No silent source exists:**
- **Contacts "Me" card:** the API that returns it only exists on macOS. On iOS, the app would need full Contacts access and still couldn't tell which contact is the user.
- **Device name:** since iOS 16, `UIDevice.current.name` just returns "iPhone" unless Apple grants a special entitlement. They don't grant it for this.
- **CloudKit:** we already have the entitlement, but the user-discoverability permission that gave apps the user's name was deprecated in iOS 17.
- **HealthKit:** it has no name field. Clinical records contain patient details, but reading them to get a name would break Article V.2 (collect only what a feature needs).

**Two options that take one tap:**
1. **Sign in with Apple, asking for the full name.** This matches the prototype's "Continue with Apple" button. The catches:
   - Apple sends the name only the first time the user authorizes. After a reinstall you get nothing, so you'd need a text field as a fallback anyway.
   - It needs a new Sign in with Apple entitlement.
   - The app gets an Apple ID credential it has no use for.
   - It looks a lot like the accounts infrastructure the brief says not to build.
   - Architecturally, the sign-in sheet is system UI, so by Article I.6 a data source would present it.
2. **A name field that AutoFill fills from the Me card.** Setting `.textContentType(.givenName)` on the field makes the keyboard suggest the user's first name, and they tap it. It needs no permission or entitlement, and the app sees nothing until the user taps.

**I'd recommend option 2.** It's the simplest (Article III.1), and option 1 would need the same field as a fallback. Either way, the name ends up in whatever real storage replaces `EmptyUserProfileDataSource`. That storage stays on the device, because Article V.1 lets only the drink log sync.

It's also worth deciding whether onboarding asks for a name at all. The greeting already works without one.
